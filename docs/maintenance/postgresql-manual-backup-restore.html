Procedimiento manual PostgreSQL 15 Issue #632

Respaldo previo al despliegue y restauración local de contingencia

Guía operativa para crear, comprobar y copiar un respaldo de PostgreSQL antes de un despliegue de Hive API que pueda ejecutar migraciones. También conserva el procedimiento de restauración en un contenedor local desechable, que solo se utiliza manualmente si se necesita recuperar datos.

Regla principal

PROHIBIDO RESTAURAR SOBRE PRODUCCIÓN Esta guía solo crea un respaldo en producción. La restauración se realiza exclusivamente en un contenedor local, nuevo y desechable. Ningún comando de este documento reemplaza, vacía ni recrea la base de datos de producción.

No iniciar el despliegue hasta que el respaldo haya superado las cuatro comprobaciones inmediatas en el VPS, se haya copiado al equipo local y su SHA-256 local coincida. La restauración local no es un requisito previo: es una contingencia manual para una necesidad real de recuperación.

1. Alcance y límites

Este procedimiento sí cubre

  • Un respaldo manual inmediatamente antes del despliegue.
  • Comprobación de salida, tamaño, SHA-256 y catálogo del archivo.
  • Copia manual del VPS al equipo del mantenedor.
  • Procedimiento de contingencia para restaurar y revisar el respaldo en PostgreSQL 15 local desechable, solo si se necesita recuperar datos.

Este procedimiento no cubre

  • Programación, cron, retención, alertas o monitorización.
  • RPO, RTO, SLA, S3, otro VPS o servicios de respaldo.
  • Restauración automática o restauración en producción.
  • Salud, acceso, inicio de sesión o sincronización de Hive API.

Las comprobaciones de aplicación se ejecutan directamente en producción o dentro del alcance de la issue #631. Los fragmentos históricos de docs/INFRASTRUCTURE.md no son el procedimiento autoritativo para esta operación; esta guía es el procedimiento específico y acotado de la issue #632.

2. Requisitos previos

  • Acceso SSH al VPS con permiso para ejecutar Docker Compose.
  • Despliegue presente normalmente en /opt/hive-api/hive-api/deploy.
  • Servicio Compose postgres en ejecución.
  • Espacio libre suficiente en el VPS y en el equipo local.
  • scp disponible en el equipo local para completar el respaldo previo al despliegue.
  • Docker disponible en el equipo local únicamente si se necesita ejecutar la contingencia de restauración.
  • Ningún despliegue ni migración en curso mientras se crea el respaldo.
No mostrar secretos. No ejecute cat .env, no copie su contenido y no introduzca credenciales reales en esta guía. Los comandos del VPS usan POSTGRES_USER y POSTGRES_DB ya disponibles dentro del contenedor postgres.

3. Crear y comprobar el respaldo en el VPS

Abra una sesión SSH dedicada. Todos los comandos de esta sección se ejecutan en el VPS. Si cualquier comprobación falla, la sesión termina con error para impedir que se continúe por accidente.

3.1 Confirmar ubicación y estado de PostgreSQL

Ejecutar en el VPS 
cd /opt/hive-api/hive-api/deploy
COMPOSE_FILE="docker-compose.prod.yml"

test -f "$COMPOSE_FILE" || { printf 'ERROR: no se encuentra %s\n' "$COMPOSE_FILE"; return 1 2>/dev/null || exit 1; }
docker compose -f "$COMPOSE_FILE" ps postgres
docker compose -f "$COMPOSE_FILE" exec -T postgres sh -c \
  'exec pg_isready --username="$POSTGRES_USER" --dbname="$POSTGRES_DB"' \
  || { printf 'ERROR: PostgreSQL no está disponible. NO DESPLEGAR.\n' >&2; return 1 2>/dev/null || exit 1; }
Resultado esperado: el servicio postgres aparece en ejecución y pg_isready informa que acepta conexiones. Si la ruta real difiere, cambie primero al directorio que contiene docker-compose.prod.yml; no cambie el nombre del servicio.

3.2 Crear un volcado en formato personalizado

Ejecutar en el VPS 
umask 077
BACKUP_DIR="$HOME/hive-api-backups"
BACKUP_NAME="hive-api-predeploy-$(date -u +%Y%m%dT%H%M%SZ).dump"
BACKUP_FILE="$BACKUP_DIR/$BACKUP_NAME"
mkdir -p -- "$BACKUP_DIR"

docker compose -f "$COMPOSE_FILE" exec -T postgres sh -c \
  'exec pg_dump --username="$POSTGRES_USER" --dbname="$POSTGRES_DB" --format=custom --no-owner --no-privileges' \
  > "$BACKUP_FILE"
DUMP_STATUS=$?

if [ "$DUMP_STATUS" -ne 0 ]; then
  printf 'ERROR: pg_dump terminó con código %s. NO DESPLEGAR. Archivo incompleto: %s\n' "$DUMP_STATUS" "$BACKUP_FILE" >&2
  return "$DUMP_STATUS" 2>/dev/null || exit "$DUMP_STATUS"
fi
printf 'OK: pg_dump terminó con código 0.\n'
Evidencia 1: aparece OK: pg_dump terminó con código 0. El archivo se crea en el sistema de archivos del VPS mediante redirección en el host, no dentro del contenedor.

3.3 Comprobar tamaño, SHA-256 y catálogo

Ejecutar en el VPS, en la misma sesión 
if ! test -s "$BACKUP_FILE"; then
  printf 'ERROR: el respaldo está vacío. NO DESPLEGAR: %s\n' "$BACKUP_FILE" >&2
  return 1 2>/dev/null || exit 1
fi
printf 'OK: respaldo no vacío: '
du -h "$BACKUP_FILE"

if ! (
  cd "$BACKUP_DIR"
  sha256sum "$BACKUP_NAME" > "$BACKUP_NAME.sha256"
  cat "$BACKUP_NAME.sha256"
  sha256sum --check "$BACKUP_NAME.sha256"
); then
  printf 'ERROR: no se pudo crear o verificar SHA-256. NO DESPLEGAR.\n' >&2
  return 1 2>/dev/null || exit 1
fi

docker compose -f "$COMPOSE_FILE" exec -T postgres \
  pg_restore --list < "$BACKUP_FILE" > "$BACKUP_FILE.list"
LIST_STATUS=$?
if [ "$LIST_STATUS" -ne 0 ] || ! test -s "$BACKUP_FILE.list"; then
  printf 'ERROR: pg_restore --list no pudo leer el respaldo. NO DESPLEGAR.\n' >&2
  return 1 2>/dev/null || exit 1
fi

chmod 600 "$BACKUP_FILE" "$BACKUP_FILE.sha256" "$BACKUP_FILE.list"
printf 'OK: catálogo legible; entradas: '
wc -l < "$BACKUP_FILE.list"
printf 'RUTA_DUMP=%s\nRUTA_SHA256=%s\n' "$BACKUP_FILE" "$BACKUP_FILE.sha256"
Evidencias 2–4:
  • du muestra un tamaño mayor que cero.
  • sha256sum --check muestra el nombre del archivo seguido de OK.
  • pg_restore --list termina con código 0 y genera un catálogo con entradas.
Conserve las rutas impresas: se usarán desde el equipo local.

4. Copiar el respaldo al equipo local

Sustituya los marcadores entre <...>. Use exactamente la ruta absoluta mostrada como RUTA_DUMP en el VPS.

Ejecutar en el equipo local 
umask 077
LOCAL_DIR="$HOME/hive-api-backups"
REMOTE_DUMP="/home/<VPS_USER>/hive-api-backups/<NOMBRE_EXACTO>.dump"
mkdir -p -- "$LOCAL_DIR"
chmod 700 "$LOCAL_DIR"

scp "<VPS_USER>@<VPS_HOST>:${REMOTE_DUMP}" "$LOCAL_DIR/" \
  || { printf 'ERROR: no se pudo copiar el respaldo.\n' >&2; return 1 2>/dev/null || exit 1; }
scp "<VPS_USER>@<VPS_HOST>:${REMOTE_DUMP}.sha256" "$LOCAL_DIR/" \
  || { printf 'ERROR: no se pudo copiar la suma SHA-256.\n' >&2; return 1 2>/dev/null || exit 1; }

LOCAL_BACKUP_FILE="$LOCAL_DIR/$(basename "$REMOTE_DUMP")"
if ! (
  cd "$LOCAL_DIR"
  sha256sum --check "$(basename "$REMOTE_DUMP").sha256"
); then
  printf 'ERROR: la suma SHA-256 local no coincide. NO RESTAURAR NI DESPLEGAR.\n' >&2
  return 1 2>/dev/null || exit 1
fi
Resultado esperado: ambas copias terminan correctamente y la comprobación local muestra OK. Un hash distinto significa que la copia local no está validada: elimine únicamente la copia local defectuosa y repita scp.
Fin de la ruta obligatoria antes del despliegue. Si pg_dump terminó correctamente, el archivo no está vacío, su SHA-256 y su catálogo son válidos, la copia local existe y el SHA-256 local coincide, puede continuar con el despliegue supervisado. No ejecute la restauración siguiente como ensayo previo.

5. Contingencia: restaurar en PostgreSQL local desechable

Ejecutar solo si se necesita recuperar datos. Esta sección no forma parte de la preparación ni de la autorización del despliegue. Es un procedimiento manual de contingencia para inspeccionar el respaldo recuperado en un PostgreSQL 15 local y aislado.
LÍMITE DESTRUCTIVO Los siguientes comandos crean y posteriormente eliminan un contenedor local cuyo nombre empieza por hive-api-restore-. No use nombres de contenedores existentes. No publique puertos y no apunte ninguna orden a un servidor remoto.

5.1 Crear una base de datos local vacía

Ejecutar en el equipo local, en la misma sesión 
RESTORE_CONTAINER="hive-api-restore-$(date -u +%Y%m%dT%H%M%SZ)"
RESTORE_USER="hive_restore"
RESTORE_DB="hive_restore"
RESTORE_PASSWORD="disposable-local-only"

docker run --detach \
  --name "$RESTORE_CONTAINER" \
  --env POSTGRES_USER="$RESTORE_USER" \
  --env POSTGRES_PASSWORD="$RESTORE_PASSWORD" \
  --env POSTGRES_DB="$RESTORE_DB" \
  postgres:15-alpine

for ATTEMPT in $(seq 1 30); do
  if docker exec "$RESTORE_CONTAINER" pg_isready --username="$RESTORE_USER" --dbname="$RESTORE_DB"; then
    break
  fi
  if [ "$ATTEMPT" -eq 30 ]; then
    printf 'ERROR: PostgreSQL local no estuvo disponible a tiempo.\n' >&2
    return 1 2>/dev/null || exit 1
  fi
  sleep 1
done
Resultado esperado: pg_isready informa que la base acepta conexiones. La contraseña es exclusivamente local y temporal; no es una credencial de infraestructura.

5.2 Restaurar el archivo con detención ante el primer error

Ejecutar en el equipo local 
test -s "$LOCAL_BACKUP_FILE" || { printf 'ERROR: no existe un respaldo local válido.\n' >&2; return 1 2>/dev/null || exit 1; }

docker exec -i "$RESTORE_CONTAINER" sh -c \
  'exec pg_restore --username="$POSTGRES_USER" --dbname="$POSTGRES_DB" --no-owner --no-privileges --exit-on-error' \
  < "$LOCAL_BACKUP_FILE"
RESTORE_STATUS=$?

if [ "$RESTORE_STATUS" -ne 0 ]; then
  printf 'ERROR: la restauración terminó con código %s. RECUPERACIÓN LOCAL NO VALIDADA.\n' "$RESTORE_STATUS" >&2
  return "$RESTORE_STATUS" 2>/dev/null || exit "$RESTORE_STATUS"
fi
printf 'OK: restauración local terminada con código 0.\n'
Resultado esperado: pg_restore termina con código 0. La opción --exit-on-error evita aceptar una restauración parcial como prueba válida.

5.3 Inspeccionar el esquema y recuentos representativos

Los nombres users, memories, sessions y user_prompts corresponden a tablas vigentes verificadas en las migraciones actuales de Hive API.

Ejecutar en el equipo local 
docker exec "$RESTORE_CONTAINER" sh -c \
  'exec psql --username="$POSTGRES_USER" --dbname="$POSTGRES_DB" --set=ON_ERROR_STOP=1 --command="\dt public.*"'

docker exec "$RESTORE_CONTAINER" sh -c \
  'exec psql --username="$POSTGRES_USER" --dbname="$POSTGRES_DB" --set=ON_ERROR_STOP=1 --command="
    SELECT '\''users'\'' AS tabla, count(*) AS filas FROM users
    UNION ALL SELECT '\''memories'\'', count(*) FROM memories
    UNION ALL SELECT '\''sessions'\'', count(*) FROM sessions
    UNION ALL SELECT '\''user_prompts'\'', count(*) FROM user_prompts
    ORDER BY tabla;
  "'
Resultado esperado: \dt public.* muestra las tablas restauradas y la segunda consulta devuelve cuatro filas con recuentos numéricos. Los recuentos pueden ser cero; lo importante es que las tablas existen y las consultas terminan sin errores. No consulte columnas con datos privados.

5.4 Eliminar el contenedor local desechable

Ejecutar en el equipo local 
case "$RESTORE_CONTAINER" in
  hive-api-restore-*) docker rm --force "$RESTORE_CONTAINER" ;;
  *) printf 'ERROR: nombre inesperado; no se elimina ningún contenedor: %s\n' "$RESTORE_CONTAINER" >&2; return 1 2>/dev/null || exit 1 ;;
esac
Resultado esperado: Docker imprime el nombre del contenedor eliminado. El archivo local y su suma SHA-256 se conservan.

6. Decisión compacta de recuperación

SituaciónDecisión inmediata
Falla pg_dump, el archivo está vacío o pg_restore --list falla.No desplegar. Conservar el mensaje de error, corregir la causa y crear un respaldo nuevo.
El SHA-256 local no coincide.No restaurar ni desplegar. Repetir la copia desde el VPS y volver a comprobarla.
Las comprobaciones del VPS, la copia local y el SHA-256 local terminan correctamente.Registrar las evidencias y proceder con el despliegue supervisado. No ejecutar la restauración local como requisito previo.
Una migración posterior falla en producción o surge una necesidad real de recuperación.Detener el despliegue o la operación afectada y seguir el plan de recuperación aprobado. Si se requiere inspeccionar el respaldo, ejecutar manualmente la contingencia local de la sección 5. Esta guía no autoriza una restauración en producción.
La restauración local de contingencia o una consulta de esquema falla.No considerar válido ese intento de recuperación. Conservar temporalmente el contenedor para diagnóstico; después eliminarlo de forma explícita. Las comprobaciones de Hive API pertenecen a producción o a la issue #631.

7. Resolución de problemas

SíntomaComprobación segura
Compose no encuentra el archivo o el servicio.Confirme pwd, test -f docker-compose.prod.yml y docker compose -f docker-compose.prod.yml ps postgres. No abra ni muestre .env.
pg_dump informa un error de conexión.Compruebe que postgres esté saludable. Los nombres de usuario y base se toman del entorno interno del contenedor.
No space left on device.No despliegue. Libere espacio mediante el procedimiento operativo habitual sin borrar respaldos no revisados y vuelva a crear el archivo desde cero.
scp informa ruta inexistente.Copie literalmente la ruta RUTA_DUMP impresa en el VPS. Compruebe el usuario remoto y no use comodines.
Ya existe el contenedor local.No reutilice ni elimine un contenedor desconocido. Genere otro nombre con una marca temporal nueva.
pg_restore termina con error.Revise su salida y docker logs "$RESTORE_CONTAINER". No añada opciones para ignorar errores y no convierta una restauración parcial en evidencia válida.

8. Listas finales

Antes del despliegue

  • pg_dump terminó con código 0 en el VPS.
  • El archivo del VPS existe, no está vacío y tiene permisos restrictivos.
  • La suma SHA-256 fue creada y verificada en el VPS.
  • pg_restore --list leyó el archivo y produjo un catálogo no vacío.
  • El archivo y su suma se copiaron manualmente al equipo local.
  • La suma SHA-256 local coincide.
  • No se ejecutó ninguna restauración como ensayo o requisito previo al despliegue.

Solo si se necesita recuperar datos

  • La restauración en postgres:15-alpine terminó con código 0.
  • El esquema y los recuentos representativos se consultaron sin errores.
  • El contenedor local desechable fue eliminado.
  • No se ejecutó ni se preparó ninguna restauración sobre producción.
Fin del procedimiento de la issue #632. Este documento no instala automatización, no programa futuros respaldos y no valida el comportamiento de Hive API. Antes del despliegue exige únicamente un respaldo manual legible, verificado y copiado. La restauración local se reserva para una contingencia de recuperación.
Procedimiento enfocado para el mantenedor de Hive API durante el despliegue interno inicial. Documento estático, autocontenido y sin dependencias de red.

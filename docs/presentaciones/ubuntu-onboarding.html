Tu primera sesión con Jarvis

Un recorrido sugerido para instalar, configurar y comprobar Jarvis. Los hitos de los primeros 15 minutos son orientativos, no tiempos garantizados ni resultados de una instalación observada.

Ruta orientativa de los primeros 15 minutos

Hitos sugeridos, no plazos ni resultados observados. Detente si necesitas soporte.

  1. Preparar: confirma terminal, red y agente elegido. Criterio observable: puedes abrir la terminal e identificar la integración prevista.
  2. Instalar: ejecuta el comando documentado. Criterio observable: la terminal reconoce jarvis o registras el fallo.
  3. Configurar: abre jarvis. Criterio observable: completas el asistente o identificas dónde se detuvo.
  4. Verificar: ejecuta jarvis verify --provider all. Criterio observable: obtienes diagnósticos reales, incluso si muestran incidencias; esto no acredita memoria ni sincronización.

1. Antes de empezar

Para quien utiliza Ubuntu o Linux y quiere preparar un agente compatible mediante la CLI. Necesitas una terminal con curl y bash, conexión para descargar la versión de producción publicada y el agente que vayas a configurar (por ejemplo, Claude Code u OpenCode). Consulta con tu equipo qué integración y credenciales te corresponden; no compartas claves ni captures datos privados.

Si utilizas Ubuntu bajo WSL, sigue estos comandos dentro de la distribución Linux, no en PowerShell. No se afirma aquí una certificación independiente de WSL. Para Windows nativo, consulta la guía de PowerShell.

2. Hito sugerido: instalar

En la terminal, ejecuta el instalador documentado para la última versión de producción publicada. Revisa el origen del script según la política de tu organización. Este comando no acredita por sí solo una instalación limpia verificada.

curl -sSL https://raw.githubusercontent.com/Thrasno/jarvis-ai-devs/master/scripts/install.sh | bash

Según la documentación, el instalador instala en /usr/local/bin. Comprueba que esa ubicación esté en el PATH; si hay problemas de permisos o descarga, no cambies la política del sistema a ciegas: consulta con soporte.

3. Hito sugerido: primera configuración

Ejecuta jarvis. En una instalación nueva se espera el asistente de configuración; en otra ya configurada se abre la reconfiguración con valores previos. Elige solo las integraciones que efectivamente utilizas (por ejemplo, Claude Code u OpenCode) y sigue las opciones que muestre tu versión. No hay un conjunto universal de pantallas ni una selección obligatoria para todos los equipos.

4. Hito sugerido: verificar

Después de completar el asistente, utiliza Jarvis para comprobar las configuraciones disponibles:

jarvis verify --provider all

Qué significa: el comando aporta diagnósticos de la configuración local. Revisa los resultados para distinguir integraciones configuradas de proveedores no seleccionados o pendientes. Una ejecución sin errores relevantes para tu integración no demuestra por sí sola autenticación del agente, arranque de Hive, sincronización compartida ni persistencia de memoria.

Evidencia pendiente: las capturas del asistente compartido no sustituyen las capturas de instalación, de jarvis verify ni de una incidencia observada en Ubuntu. Faltan esos resultados verificables y la primera experiencia de memoria en el equipo de destino. La prueba de memoria con el agente se mostrará en la demo o sesión individual; esta guía no la da por superada.

Si algo falla

Si falla la descarga, comprueba la red y el acceso al origen con soporte. Si jarvis no se encuentra, comprueba el PATH y los permisos de instalación sin alterar la seguridad del sistema. Si la verificación señala una integración, revisa la selección en jarvis y consulta instalación, primeros pasos y configuración; traslada el mensaje exacto, sin credenciales, al equipo responsable.

5. Elige tu siguiente paso

  • Desarrollador: abre un repositorio de prueba con el agente seleccionado y comprueba que carga la configuración generada.
  • Responsable de equipo: acuerda con el grupo qué agente se configurará y reúne incidencias de la verificación sin recopilar secretos.
  • Administrador de Hive: prepara por separado el daemon local y, si procede, las credenciales y políticas del Hive API; consulta configuración.
  • Evaluador: anota versión, selección y resultado real de verificación, incluidos los pasos no comprobados.
  • Formador: reserva una demostración guiada del comportamiento de memoria a través del agente; no presentes una captura pendiente como prueba.

# Uncertainty and safe exclusions

Ask only missing facts that change routing or prevent safe generation. If one verified path remains, state it and proceed; if materially equivalent paths require a product choice, recommend one and wait for selection.

Unknown plan gates, quotas, and costs require a warning and runtime validation. Do not invent values, tenant support, task names, endpoints, scopes, identities, workflow controls, response shapes, event behavior, or permissions. Surface known permission failures instead of hiding them.

Custom API generation remains unavailable because its official management contract, scopes, limits, and plan gate were not accessible for review. Unavailable surfaces fail closed; offer a verified alternative or request newly reviewed official evidence.

Do not request secrets. When routing cannot proceed, name the missing runtime fact or evidence boundary and return unsupported rather than fabricating a capability.
